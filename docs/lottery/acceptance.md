# Acceptance map — the 25 criteria of spec §13

This page is the proof that the automated weekly lottery does what
[the spec](../user-stories/automated-weekly-lottery.md) §13 says. It was assembled for #116 by walking the 25
acceptance criteria and pointing each one at the test that proves it. Two criteria cannot be automated (Discord's
ephemeral replies and the Vue UI); they are listed under [Manual checks](#manual-checks) with the reason.

Path convention: test files are relative to `ExcelBotCs.Tests/`. The test class is named once, then only the test
methods are listed.

## How to run the proof

```bash
dotnet build ExcelBotCs.sln
DOTNET_CLI_HOME=$PWD/.scratch/dotnet-home DOTNET_CLI_TELEMETRY_OPTOUT=1 \
  DOCKER_HOST=unix://$PWD/.scratch/podman.sock TESTCONTAINERS_RYUK_DISABLED=true \
  dotnet vstest ExcelBotCs.Tests/bin/Debug/net9.0/ExcelBotCs.Tests.dll \
                ExcelBotCs.TestFramework.Tests/bin/Debug/net9.0/ExcelBotCs.TestFramework.Tests.dll
```

`dotnet test` is unreliable on this machine — see `AGENTS.md`. A single criterion can be re-checked with
`--TestCaseFilter:"FullyQualifiedName~LotteryAdminIntegrationTests"` and friends.

## Manual checks

Three things cannot be asserted from the test suite. Each is a UI or Discord-gateway behaviour, and none of them is
business logic that could silently regress without a visible symptom.

| What | Why it is manual | How to check |
|---|---|---|
| The opt-out button replies **ephemerally**, and `/lottery reminders` / `/lottery remind` answer ephemerally | Discord's interaction reply target (`SocketInteractionContext`) needs a live gateway socket; the test suite deliberately never connects one. The *effect* of the button — only the caller's opt-in changes, idempotently, also after leaving the FC — is covered by `LotteryReminderServiceTests.SetPreferenceOff_*`, and the component routing by `LotteryInteractionPermissionTests.TheReminderOptOutButtonIsAComponentHandlerOnTheSameModule` | Click **Turn off reminders** in the lottery channel as a non-officer member; the reply is only visible to the caller and the opt-in disappears from `/lottery/admin` → **Schedule & reminders** → **Opted-in members** |
| The Vue pages: five admin tabs, confirm dialogs, infinite scroll with the `IntersectionObserver`, **Load more winners**, empty/loading/mobile layout | The repo has no frontend test runner (`AGENTS.md`); the pages are typed-checked and built instead | `cd ExcelBotCs/ClientApp && npx vue-tsc --noEmit && npm run build`, then browse `/lottery`, `/lottery/history` and `/lottery/admin` |
| The announcement is **not pinned** and the reminder post carries the opt-out button | The Discord message seam exposes content and mentions only; a pin is an out-of-band call the bot never makes | Look at the channel after a run: nothing is pinned; the reminder message shows the button |

## Notes from #116

- **The reminder is now gated by the startup verdict** (`startup-pending` / `startup-degraded` dispositions), so a
  degraded start disables the draw *and* the reminder. Criterion 19's reminder tests above — and the registration test
  that proves the host injects the verdict — are the regression guard. The officer's manual reminder and the admin
  test send stay live, exactly like the manual **Run now**.
- **The `lottery` health detail follows the accepted #105 rule**: the round state decides the status; `dry-run`,
  `paused` and `disabled` are reported in `automationNote` without degrading the probe. The two new
  `CheckHealthAsync_*` tests are the regression guard.

## Keeping this map honest

When a test named here is renamed or removed, update this page in the same commit. A criterion with no test must be
moved to [Manual checks](#manual-checks) with the reason — never left pointing at a test that does not exist.
